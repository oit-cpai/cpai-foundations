R3 では、方策の価値を連立一次方程式として解いた。しかし、最適な方策を求める式(ベルマン最適方程式)は $\max$ を含むので、そのままでは解けなかった。この単元では、ベルマン方程式を**くり返し使う**ことで、どちらも解く。この方法を**動的計画法**(DP、Dynamic Programming)という。

> [!IMPORTANT]
> 動的計画法は、環境のモデル($P$ と $R$)が**分かっている**ことを前提にする。環境と一度もやりとりせずに、計算だけで最適な方策を求める。これを**計画**といい、試行錯誤で価値を推定する**学習**と区別する。R5 以降は、モデルが分からないときの方法である。

## 1. 方策評価:ベルマン方程式をくり返す

R3 の式 (3) の右辺を、次の価値を作る**更新の式**として使う。

```math
V_{k+1}(s) = \sum_{a} \pi(a \mid s) \left[ R(s, a) + \gamma \sum_{s'} P(s' \mid s, a)\, V_k(s') \right] \qquad (1)
```

すべての状態を0にした $V_0$ から始めて、式 (1) をくり返すと、 $V_k$ は方策の価値 $V^{\pi}$ に近づく。これを**反復方策評価**という。

**なぜ近づくのか**:真の価値 $V^{\pi}$ は式 (1) を満たす(R3 の式 (3))。式 (1) から $V^{\pi}$ の式を引くと、

```math
\max_s \lvert V_{k+1}(s) - V^{\pi}(s) \rvert \le \gamma \max_s \lvert V_k(s) - V^{\pi}(s) \rvert
```

となる。1回くり返すごとに、誤差が $\gamma$ 倍**以下**に縮む。これは上限で、 $\gamma = 0.95$ なら、誤差を $10^{-10}$ 倍にするのに、多くても $\log(10^{-10}) / \log(0.95) \approx 450$ 回で済む、という意味である。

実際の速さは、方策によって変わる。ゴールに着くと終わる問題では、ゴールに着いたあとの価値は0のまま変わらないので、**まだゴールに着いていない確率の分だけ、さらに速く**縮む。notebook では、すぐにゴールに着く方策(約40回)と、ほとんどゴールに着かない方策(約400回)で、くり返しの回数を比べる。

**いつ止めるか**:1回のくり返しでの変化 $`\max_s \lvert V_{k+1}(s) - V_k(s) \rvert`$ が、決めた小さな値(例:$10^{-8}$)より小さくなったら止める。

**配列で書く**:`P` が形 `(S, A, S)`、`V` が長さ `S` の配列なら、`P @ V` は形 `(S, A)` の配列で、要素は $`\sum_{s'} P(s' \mid s, a)\, V(s')`$ である。したがって、

| コード | 式 |
|---|---|
| `Q = R + gamma * P @ V` | $`Q(s, a) = R(s, a) + \gamma \sum_{s'} P(s' \mid s, a)\, V(s')`$ |
| `V_new = Q[np.arange(S), policy]` | 決定的な方策 $\pi$ が選ぶ行動の $Q$(式 (1)) |
| `V_new = Q.max(axis=1)` | 一番良い行動の $Q$(§4 の価値反復) |
| `Q.argmax(axis=1)` | 各状態で $Q$ が最大の行動(§2 の方策改善) |

`for` 文で状態ごとに計算しなくても、1行で全状態を更新できる。

## 2. 方策改善:価値を見て、良い行動に変える

方策 $\pi$ の価値 $V^{\pi}$ が分かったら、各状態で「1ステップ先を見て、一番良い行動」を選ぶ方策 $\pi'$ を作る。

```math
\pi'(s) = \operatorname*{argmax}_{a} \left[ R(s, a) + \gamma \sum_{s'} P(s' \mid s, a)\, V^{\pi}(s') \right] = \operatorname*{argmax}_{a} Q^{\pi}(s, a) \qquad (2)
```

これを、 $V^{\pi}$ に対する**貪欲な(greedy)方策**という。

たとえば、ある状態の行動価値 `Q[s]` が `[3, 7, 5]` なら、`Q[s].max()` は最大の**価値** `7` を返す。`Q[s].argmax()` はその価値を与える**行動の番号**を 0 から数えて返すので、式 (2) で選ぶのは行動 `1` である。

> [!NOTE]
> **方策改善定理**:式 (2) で作った方策 $\pi'$ は、すべての状態で、もとの方策 $\pi$ と同じかそれより良い($V^{\pi'}(s) \ge V^{\pi}(s)$)。さらに、式 (2) で方策が変わらなければ、 $V^{\pi}$ は R3 のベルマン最適方程式を満たしている。つまり、 $\pi$ は最適な方策である。

## 3. 方策反復

方策評価(§1)と方策改善(§2)を、交互にくり返す。

```text
π0 → (評価) V^π0 → (改善) π1 → (評価) V^π1 → (改善) π2 → … → 方策が変わらなくなったら終わり
```

方策は改善のたびに良くなり(方策改善定理)、決定的な方策の数は有限なので、**有限回で最適な方策に着く**。小さなグリッドなら、外側のくり返しは数回で終わることが多い。

## 4. 価値反復

方策反復では、改善の1回ごとに、方策評価を収束するまでくり返す。これは重い。そこで、評価を1回の更新で打ち切り、そのまま改善($\max$)と合わせる。

```math
V_{k+1}(s) = \max_{a} \left[ R(s, a) + \gamma \sum_{s'} P(s' \mid s, a)\, V_k(s') \right] \qquad (3)
```

これは、R3 のベルマン最適方程式 (5) を更新の式にしたものである。 $V_k$ は最適な価値 $V^{\ast}$ に近づき、誤差は1回ごとに $\gamma$ 倍以下に縮む(§1 と同じ理由)。収束したら、式 (2) で方策を1回求めれば、それが最適な方策になる。これを**価値反復**という。

| | 方策反復 | 価値反復 |
|---|---|---|
| くり返す式 | ベルマン方程式(評価)と、改善 | ベルマン最適方程式 |
| 方策 | 毎回持つ | 最後に1回だけ求める |
| 1回のくり返しの計算 | 重い(評価を収束までくり返す) | 軽い(1回の更新) |
| くり返しの回数 | 少ない(有限回で終わる) | 多い(誤差が小さくなるまで) |
| 途中の $V$ の意味 | ある方策の価値 | どの方策の価値でもない途中の値 |

R5 で使う `value_iteration` は、この価値反復である。

## 5. 最適な方策を読む

この単元の notebook では、R2 のグリッド(滑る床、ぬかるみ)で最適な方策を求め、矢印で表示する。次の点に注目する。

- **ぬかるみの近くでの行動**:滑る床では、ぬかるみの隣を通るだけで、滑ってぬかるみに入る危険がある。最適な方策は、少し遠回りしてでも、ぬかるみから離れることがある
- **割引率の影響**:$\gamma$ を小さくすると、遠くの報酬(ゴールに早く着くこと)を軽く見るので、価値が変わる。ゴールにほとんど着かない方策の評価では、 $\gamma$ が 1 に近いほど、収束までのくり返しの回数が大きく増える

> [!TIP]
> **結果を確かめる習慣**:価値反復で求めた最適な価値 $V^{\ast}$ は、R3 の式 (4) で「求めた方策の価値」を計算して、一致することを確かめられる。また、方策反復と価値反復で、最適な価値が一致することも確かめる。研究でも、学習した結果を、このような「正解」と比べて確かめる(R5〜R8)。

## 6. 動的計画法の限界

- **モデルが必要**:$P$ と $R$ が分からない問題(実際のロボット、相手のいるゲーム)では使えない。そのときは、経験からモデルを推定する(R5)か、経験から直接価値を学ぶ(R6・R7)
- **状態が多いと計算できない**:1回の更新の計算量は、およそ「状態の数の2乗 × 行動の数」である。状態の数は、問題の変数が増えると指数的に増える(次元の呪い)
