| 時間の目安 | 本文 1.5時間、notebook 2時間 |

| notebook | [`10_dqn.ipynb`](10_dqn.ipynb) |

R7 の Q学習は、すべての $(s, a)$ について $Q(s, a)$ の値を表に持っていた。CartPole(R9)の状態は4つの実数なので、表に入らない。この単元では、 $Q$ を**関数**(ニューラルネット)で表して Q学習を行う。これが **DQN**(Deep Q-Network)である。notebook では、PyTorch を使わず、D1 で作った NumPy のニューラルネットで実装する。

## 1. 表から関数へ

状態 $s$ を入力し、各行動の価値 $Q_\theta(s, a)$ を出力するニューラルネットを考える。CartPole なら、入力は4つ、出力は2つ(左に押す価値、右に押す価値)である。 $\theta$ はネットの重みをまとめたものである。

| | 表の Q学習(R7) | DQN |
|---|---|---|
| $Q$ の持ち方 | 表 `Q[s, a]` | ニューラルネット $Q_\theta(s, \cdot)$ |
| 1回の更新で変わるもの | 経験した `Q[s, a]` の1つだけ | 重み $\theta$ 全体(すべての状態の価値が少しずつ変わる) |
| 似た状態 | 別々に学ぶ | 近い入力には近い出力を返すので、まとめて学べる(汎化) |

## 2. TD目標への回帰

R7 の Q学習の更新 $Q(s, a) \leftarrow Q(s, a) + \alpha \left[ y - Q(s, a) \right]$ は、「 $Q(s, a)$ を TD目標

```math
y = r + \gamma\, (1 - d) \max_{b} Q(s', b) \qquad (1)
```

に近づける」ことだった。 $d$ は、 $s'$ が終わりの状態(`terminated`)なら 1、そうでなければ 0 である。DQN では、これを**回帰**の問題として書く。経験の組 $(s, a, r, s', d)$ をたくさん集め、2乗誤差

```math
L(\theta) = \frac{1}{B} \sum_{i=1}^{B} \left( Q_\theta(s_i, a_i) - y_i \right)^2 \qquad (2)
```

を小さくする方向に、勾配法で $\theta$ を動かす。 $B$ は1回に使う経験の数(ミニバッチの大きさ)である。

> [!IMPORTANT]
> **TD目標 $y$ は「正解」として扱い、 $\theta$ で微分しない。** $y$ にも $Q$ が入っているが、そこまで微分すると、目標のほうを $Q_\theta(s, a)$ に近づけてしまう。誤差逆伝播で勾配を流すのは、 $`Q_\theta(s_i, a_i)`$ の側だけである。

出力が2つあるネットで、勾配が流れるのは、**実際に選んだ行動 $a_i$ の出力だけ**である。もう一方の出力には、その経験の情報がないからである。

> [!WARNING]
> **`truncated` を $d = 1$ にしない**(R2 §2、R7 §2)。CartPole では、500 ステップに達して打ち切ったのは「棒が倒れた」のではない。 $d = 1$ にすると、まだ立っている状態の価値を低く学んでしまう。 $d$ には `terminated` だけを入れる。

## 3. なぜ、そのままでは不安定なのか

式 (2) を、集めた順に1つずつ使って学習すると、うまくいかないことが多い。理由は2つある。

1. **データが似ている**:続けて集めた経験は、ほとんど同じ状態から来ている。教師あり学習で、同じようなデータばかりを続けて学ぶと、そのデータに引きずられて、ほかの状態での予測が崩れる
2. **目標が動く**:TD目標 $y$ は $Q_\theta$ を使って作るので、 $\theta$ を更新すると、目標も変わる。回帰の「正解」が、学ぶたびに動いてしまう

さらに、「関数で近似する」「推定で推定を直す(ブートストラップ)」「行動と違う方策を学ぶ(off-policy)」の3つが重なると、価値が発散することがある(Sutton & Barto は **deadly triad** と呼ぶ)。DQN は、次の2つの工夫で、これを抑える。

## 4. 2つの工夫

**経験の再利用(replay buffer)**:経験を大きな入れ物(バッファ)にためておき、学習のたびに、そこから**一様にランダムに**ミニバッチを取り出す。続けて集めた似た経験が、同じミニバッチに偏らない。1つの経験を何度も使えるので、環境とのやりとりも少なくてすむ。

**目標ネットワーク(target network)**:TD目標を作るためのネット $Q_{\theta^-}$ を別に用意し、その重み $\theta^-$ は、一定のステップごと(notebook では 500 ステップごと)に $\theta$ をコピーするだけにする。

```math
y = r + \gamma\, (1 - d) \max_{b} Q_{\theta^-}(s', b) \qquad (3)
```

コピーとコピーのあいだは、目標が止まっているので、普通の回帰に近くなる。

| 工夫 | 防ぐもの | 取り除くと(notebook §5) |
|---|---|---|
| replay buffer | データの偏り(時間的な相関) | 学習が不安定になる。少し学んでは崩れる |
| target network | 動く目標 | 価値の推定が振動したり、大きくなりすぎたりする |

## 5. 探索:ε を少しずつ減らす

行動は、R1・R7 と同じ ε-greedy で選ぶ。ただし、最初はネットが何も知らないので、 $\varepsilon = 1$ (完全にランダム)から始め、決めたステップ数をかけて、小さな値(0.05)まで直線的に減らすことが多い。

## 6. 研究で使うときは

- **結果は seed でとても大きく変わる**:DQN の学習曲線は、seed によって大きく違い、一度うまくいったあとで崩れることもある。複数の seed で比べ、学習曲線の平均とばらつきを示す
- **ハイパーパラメータが多い**:学習率、バッファの大きさ、ミニバッチの大きさ、目標ネットワークを更新する間隔、ε の減らし方、割引率。変えるときは1つずつ変え、何を変えたかを記録する
- **評価は greedy で**:学習中の収益は ε-greedy での値である。学習の途中や最後に、ε = 0(または小さな値)で別に評価する
- **改良版**:$\max$ のせいで価値を大きめに見積もる問題(最大化の偏り)を減らす Double DQN など、多くの改良がある。研究で使うライブラリの DQN にも、いくつかが入っている

## 7. 研究室のライブラリ `cpai_lab` との関係

`cpai_lab` には、DQN は入っていない。研究では、PyTorch で書かれた強化学習のライブラリ(例:Stable-Baselines3)の DQN を使うことが多い。そのときに設定する主なものと、この単元の対応は次のとおりである。

| ライブラリの設定(例) | この単元 |
|---|---|
| `buffer_size` | replay buffer の大きさ |
| `batch_size` | ミニバッチの大きさ $B$ |
| `target_update_interval` | 目標ネットワークにコピーする間隔 |
| `exploration_fraction`、`exploration_final_eps` | ε を減らすステップ数、最後の ε |
| `learning_rate`、`gamma` | 勾配法の学習率、割引率 |

## 8. 確認課題

1. 経験 $(s, a, r, s', d)$ で、 $r = 1$ 、 $\gamma = 0.99$ 、 $Q_{\theta^-}(s', \cdot) = (12, 15)$ のとき、 $d = 0$ と $d = 1$ のそれぞれで TD目標を求めよ
2. CartPole で、ステップ 500 で打ち切られた経験に $d = 1$ を入れると、どの状態の価値がどうずれるか
3. replay buffer から、最近の経験だけを取り出して学習すると、何が問題か
4. 目標ネットワークをコピーする間隔を 1 ステップにすると、何もしない場合とどう違うか
5. 表の Q学習では、ある $(s, a)$ を更新しても、ほかの $(s, a)$ の値は変わらなかった。DQN ではどうか。それが良い点と悪い点を1つずつ挙げよ
