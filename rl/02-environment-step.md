# R2 環境を作る:`reset()` と `step()`

| 項目 | 内容 |
|---|---|
| 到達目標 | エージェントと環境のやりとり(相互作用のループ)を説明できる。小さなグリッドの環境を、`reset()` と `step()` を持つクラスとして自分で作れる。`terminated` と `truncated` の違いを説明できる。乱数の入った環境で、方策の良さを複数の seed で比べられる |
| 前提 | M1(配列、添字)、M2(確率、標本平均のばらつき) |
| 時間の目安 | 本文 1時間、notebook 2時間 |
| 使う場面 | 強化学習のすべての単元。卒研で、シミュレータを自分の問題に合わせて作る・直すとき |
| notebook | [`02_environment_step.ipynb`](02_environment_step.ipynb) |

強化学習では、**エージェント**(行動を決める側)と**環境**(行動の結果を返す側)が、交互にやりとりを続ける。この単元では、環境の側を自分で作る。環境の中身が分かると、強化学習の式(R3)や、うまく学習しないときの原因(報酬の設計、終了の判定)が読めるようになる。

## 1. 相互作用のループ

```text
  エージェント                                  環境
      │  ─── 行動 a_t ───────────────────────→  │
      │                                          │ 状態を s_t から s_{t+1} に変える
      │  ←── 次の状態 s_{t+1}、報酬 r_{t+1} ───  │
      │                                          │
   (くり返す。終わったら reset() で最初に戻す)
```

1. `reset()` で、環境を最初の状態にする。最初の状態 $s_0$ が返ってくる
2. エージェントが、今の状態 $s_t$ を見て行動 $a_t$ を選ぶ
3. `step(a_t)` で環境を1ステップ進める。次の状態 $s_{t+1}$ と報酬 $r_{t+1}$ が返ってくる
4. 終わりの合図が来るまで、2〜3 をくり返す

1回の `reset()` から終わりまでを**エピソード**という。エピソードで受け取った報酬の合計が大きいほど、良い方策である(R3 で、割引を入れた「収益」として定式化する)。

## 2. `step()` が返す5つの値

研究でよく使うライブラリ Gymnasium の約束に合わせて、`step(action)` は次の5つを返す。

| 値 | 意味 |
|---|---|
| `observation` | 次の状態(このグリッドでは、マスの番号) |
| `reward` | この1ステップでもらった報酬 |
| `terminated` | 課題として終わったか(ゴールに着いた、など) |
| `truncated` | 時間切れなどで、途中で打ち切ったか |
| `info` | 補足の情報(辞書)。デバッグに使う |

`reset()` は、最初の状態と `info` の2つを返す。

> [!IMPORTANT]
> **`terminated` と `truncated` を区別する。** ゴールに着いて終わったのか(`terminated`)、時間が足りなくて打ち切ったのか(`truncated`)で、意味がまったく違う。打ち切ったエピソードでは、本当はまだ報酬が続くはずである。学習のときにこれを「終わった」と扱うと、価値を誤って見積もる(R7 で扱う)。

## 3. この単元のグリッド

R2〜R5 では、同じ環境を使う。

```text
 S  .  .  .        S = スタート(マス 0)
 .  M  .  .        G = ゴール(マス 15)
 .  .  M  .        M = ぬかるみ(マス 5 と 10)
 .  .  .  G
```

| 項目 | 内容 |
|---|---|
| 状態 | 16マス。左上から右へ、行ごとに番号を付ける(マス 0〜15) |
| 行動 | 0 = 上、1 = 右、2 = 下、3 = 左 |
| 移動 | 選んだ方向の隣のマスへ進む。外に出る方向なら、その場にとどまる |
| 滑る床 | 確率 `slip` で、選んだ行動の代わりに、4方向からランダムに選んだ方向へ進む(選んだ方向になることもある) |
| 報酬 | 1ステップごとに −1。ぬかるみのマスに入ったときは −10 |
| 終わり | ゴールに着いたら `terminated`。`max_steps` ステップで着かなければ `truncated` |

### 座標と番号

マスの位置は `(行, 列)` で考えるが、強化学習の計算では1つの整数(マスの番号)で表すと便利である。4列のグリッドでは、

```math
\text{番号} = \text{行} \times 4 + \text{列}, \qquad
\text{行} = \text{番号} \mathbin{//} 4, \quad \text{列} = \text{番号} \bmod 4
```

である。たとえば `(1, 1)` はマス 5、マス 11 は `(2, 3)` である。

## 4. `step()` を組み立てる順番

`step()` を一度に書こうとせず、次の順に作って、1つずつ確かめる。

1. **状態を覚える**:環境は、今エージェントがいるマスを、自分の変数として持つ。`reset()` でスタートに戻す
2. **次のマスを計算する**:行動の向きを足す。外に出るなら、元のマスのまま
3. **滑る床**:乱数で、行動をランダムな方向に置き換える
4. **報酬と終わりの判定**:入ったマスで報酬を決め、ゴールかどうか、時間切れかどうかを判定する
5. **状態を更新して、5つの値を返す**

> [!WARNING]
> **よくある間違い**:次のマスを計算したのに、環境の変数(今いるマス)を更新し忘れる。すると、エージェントがいつまでもスタートから動かない。`step()` を作ったら、決めた行動の列で動かして、着いたマスを確かめる。

## 5. 乱数と seed

滑る床があると、同じ方策でも、エピソードごとに結果が変わる。そのため、

- `reset(seed=...)` で乱数の種(seed)を決められるようにする。同じ seed なら、同じ結果が再現できる
- 方策の良さは、1回のエピソードではなく、**複数の seed での平均とばらつき**で比べる(M2 §3)

## 6. 研究で使うときは

- **報酬の設計で、行動が変わる**:ぬかるみの罰を小さくすると、エージェントはぬかるみを通る近道を選ぶかもしれない。報酬は「何をしてほしいか」を環境に書き込むことである
- **`max_steps` を決める**:学習の初めはでたらめに動くので、打ち切りがないとエピソードが終わらないことがある
- **自分で作った環境は、必ず手で確かめる**:決めた行動の列で動かして、位置・報酬・終わりの判定が、紙で考えたとおりになるかを確かめる

## 7. 確認課題

1. 4列のグリッドで、マス 9 は何行何列か。`(3, 2)` は何番のマスか
2. 滑らない床(`slip = 0`)で、スタートから「右・右・右・下・下・下」と動いたときの、通るマスと報酬の合計を求めよ
3. スタートで「上」を選ぶと、どうなるか。報酬はいくつか
4. `slip = 0.2` のとき、「右」を選んで実際に右へ進む確率はいくつか(選んだ方向がランダムに選ばれる場合も含める)
5. `terminated` と `truncated` の違いを、このグリッドの例で説明せよ
