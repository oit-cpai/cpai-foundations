# R5 経験からモデルを推定する

| 項目 | 内容 |
|---|---|
| 到達目標 | 経験(状態・行動・次の状態・報酬の組)から、遷移確率と報酬の平均を推定できる。推定したモデルに価値反復を使って方策を求め、その方策の良さを本当のモデルで評価できる。経験の量と方策の良さの関係を、複数の seed で確かめられる |
| 前提 | M2 §5(数えて確率を推定する)、M4 §4(価値の計算)、R4(価値反復) |
| 時間の目安 | 本文 1時間、notebook 2時間 |
| 使う場面 | モデルベース強化学習の基本。R8(Dyna-Q)の準備 |
| notebook | [`05_model_estimation.ipynb`](05_model_estimation.ipynb) |

R4 の動的計画法では、環境のモデル(遷移確率 $P(s' \mid s, a)$ と報酬 $R(s, a)$)が分かっていれば、学習しなくても最適な方策を計算できた。しかし実際には、モデルは分からないことが多い。この単元では、**経験からモデルを推定し、推定したモデルで計画する**方法を学ぶ。

## 1. 3つの立場

環境のモデルの扱い方には、大きく3つの立場がある。

| 立場 | やること | 例 |
|---|---|---|
| モデルが分かっている | モデルを使って計画する(学習は要らない) | 価値反復、方策反復(R4) |
| モデルを推定する | 経験からモデルを推定し、それを使って計画する | この単元(R5)、Dyna-Q(R8) |
| モデルを使わない | 経験から直接、価値や方策を学ぶ | モンテカルロ法(R6)、Q学習(R7) |

この単元の方法は、M2 の「数えて確率を推定する」と、R4 の「モデルを使って計画する」を組み合わせたものである。

## 2. モデルを推定する

経験の組 $(s, a, r, s')$ がたくさん集まったとする。「状態 $s$ で行動 $a$ をとったら、報酬 $r$ をもらい、次に状態 $s'$ になった」という記録である。

**遷移確率**は、回数を数えて推定する(M2 §5)。

$$
\hat{P}(s' \mid s, a) = \frac{N(s, a, s')}{N(s, a)}
$$

**報酬**は、その $(s, a)$ でもらった報酬の平均で推定する。

$$
\hat{R}(s, a) = \frac{1}{N(s, a)} \sum_{(s, a) \text{ でもらった報酬}} r
$$

**一度も試していない $(s, a)$**($N(s, a) = 0$)は推定できない。どう扱うかで、エージェントの振る舞いが変わる。

- その場にとどまり報酬 0、とする(この単元の notebook で使う)
- 一様にどこかへ移る、とする
- 「とても良いことが起きる」と楽観的に仮定する。そうすると、エージェントはまだ試していない行動を選びたがり、探索が進む(R-max などの考え方)

## 3. 推定したモデルで計画し、本当のモデルで評価する

推定したモデル $(\hat{P}, \hat{R})$ に価値反復を使えば、そのモデルにとっての最適な方策 $\hat{\pi}$ が求まる。

ここで注意が要る。推定したモデルで計算した価値は、**推定したモデルの中での価値**であり、本当の環境での価値ではない。方策 $\hat{\pi}$ の本当の良さは、**本当のモデルで $\hat{\pi}$ を評価して**確かめる。固定した方策の価値は、M4 §4 の連立方程式

$$
(I - \gamma P_{\hat{\pi}})\, v = r_{\hat{\pi}}
$$

で計算できる。$P_{\hat{\pi}}$ と $r_{\hat{\pi}}$ は、各状態で $\hat{\pi}$ が選ぶ行動についての遷移確率と報酬を並べたものである。

この単元の notebook では、本当のモデルが分かっている小さな環境を使うので、

- 本当のモデルで求めた最適な価値 $v^\ast$(正解)
- 推定したモデルから求めた方策 $\hat\pi$ の、本当の価値 $v^{\hat\pi}$

を比べられる。$v^\ast - v^{\hat{\pi}}$ が、モデルの推定が不正確なために失った価値である。

## 4. 経験の量と方策の良さ

経験が少ないと、推定したモデルは不正確になり、求めた方策も悪くなる。経験を増やすと、推定は正確になり(M2 のとおり、誤差はおよそ $1/\sqrt{N}$ で減る)、方策は最適に近づく。

ただし、すべての $(s, a)$ でモデルが正確である必要はない。最適な方策が使う $(s, a)$ のまわりで正確なら、方策は最適になりうる。逆に、たまたま一度しか試していない $(s, a)$ の推定が大きくずれると、方策が大きく悪くなることもある。

**比べ方の注意**:方法どうしを比べるときは、**環境から得た経験の数をそろえる**。また、経験の集め方には乱数が入るので、**複数の seed で平均とばらつきを示す**(M2 §3)。

この単元では簡単のため、すべての $(s, a)$ を順に、同じ回数ずつ試して経験を集める(実際の環境では、好きな状態から始められるとは限らない。その場合は、エピソードを実行しながら集める)。

## 5. Dyna-Q への道

R8 の Dyna-Q は、この単元の考え方と、R7 の Q学習を組み合わせたものである。実際に環境で行動するたびに Q学習で学び、同時に経験からモデルを推定して、そのモデルの中で「仮想の経験」を作ってさらに学ぶ。少ない実経験で効率よく学べるが、モデルが不正確だと、誤った仮想経験で学んでしまうこともある。

## 6. 確認課題

1. ある $(s, a)$ を5回試したところ、次の状態が $s_1$ に3回、$s_2$ に2回なり、報酬はそれぞれ $-1, -1, -1, -10, -1$ だった。$\hat{P}(\cdot \mid s, a)$ と $\hat{R}(s, a)$ を求めよ
2. 推定したモデルで計算した価値が、本当の価値より高くなることがある。どんなときか
3. notebook で、試していない $(s, a)$ を「楽観的」に扱う(たとえば報酬を大きな正の値にする)と、求めた方策はどう変わるか
